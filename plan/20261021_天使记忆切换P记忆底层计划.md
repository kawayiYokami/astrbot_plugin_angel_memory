# 天使记忆切换到 p-memory 底层计划

> 版本：2026-10-21（第二轮，已收敛业务决策）
> 开发工作树：.pai/.worktree/pmemory/astrbot_plugin_angel_memory（分支 feature/p-memory-migration）
> 测试环境：docker 容器 astrbot（工作树在挂载目录内，直接执行；p-memory 走 pip 依赖）

## 一、用户原始关键指令（节选）

- 「把我们项目的底层数据库换成 E:\github\pai-memory，应该有 python 依赖。参考 E:\github\story 怎么接入的。」
- 「考虑下我们项目的风格，进化一下方向，这次计划应该详细一点。」
- 「不需要原生对应，我们是直接升级到 P 记忆，我们只做提供商和后处理。」
- 「笔记系统也跟进 story 的算法。而记忆系统因为我们是短期记忆所以保留我们的部分效果。」
- 「记忆开向量，笔记不开向量。大家都开重排。」
- 「不自动召回。（群聊知识）」
- 「8 不保留旧的；9 工作树下开，测试需要在 docker 内测试。」

## 二、目标

1. 记忆、笔记、检索全部由 p-memory 承载，插件内不再保留第二套存储真相。
2. 自研部分收敛为两件事：**提供商回调**（embedding / rerank）与**后处理**（结果转换、灵魂共鸣、画像、注入、衰减退休裁决、Web 展示）。
3. 笔记链路对齐 story 的 KnowledgeBase 用法（set_root / upsert_file / 三块检索 / 单篇检索 / 路径定位）。
4. 记忆链路保留短期记忆语义：三档衰减、LLM 退休裁决、有用反馈、固定保留。

## 三、调查结论（现状事实）

### 3.1 线上数据
- 记忆 475 条，`memory_scope` 全部 `public`；类型中文枚举（知识 424、技能 27、事件 24）；`is_active=1` 251 条；`strength<=0` 79 条。
- 旧表字段：`id(TEXT) / memory_type / judgment / reasoning / strength / is_active / memory_scope / created_at / updated_at / useful_count / useful_score / last_recalled_at / last_decay_at`。
- 笔记 1315 篇：原神 629、崩坏星穹铁道 631、绝区零 45、海豹的个人信息 3（fairy 人设：对话/性格/设定）、`.angel/note` 6；旧切片 42213 条。
- 账本：`user_ledger` 128、`group_ledger` 5。
- 旧数据目录按提供商分裂：`memory_center`（122M）、`memory_硅基m3`（457M）、`memory_硅基流动嵌入`（208M）。

### 3.2 现有实现
- `MemoryRuntime` 协议两套实现：`VectorMemoryRuntime`（CognitiveService + FAISS/SQLite 向量 + HybridRetrievalEngine + MemorySqlManager）、`SimpleMemoryRuntime`（MemorySqlManager + FTS5/jieba）。
- 笔记：`NoteService` + `NoteChunkStore` + `NoteChunkSearchEngine`（Tantivy），短 ID 由 `note_short_id_seq` 维护。
- 工具：`angel_remember`（create/update/merge）、`angel_recall`、`angel_note_read`（note_short_id + offset/limit 读原文件）、`angel_note_create`。
- scope 语义：写入时由 `resolve_memory_scope` 解析（人格键优先，其次会话 ID，默认 public）；读取时非 public 的会话额外合并 public。
- Web：`memory_api` / `notes_api` / `debug_api` 直接依赖 `memory_sql_manager`、`note_chunk_search`、`vector_store` 与 FAISS 路径。
- 容器只挂载 `E:\github\ai-qq\astrbot\data`，工作树不可见。

### 3.3 p-memory 能力匹配度
- 记忆：`upsert / upsert_by_judgment / search / feedback / decay / list / ids / delete`；状态字段 `pinned / strength / useful_count / useful_score / last_recalled_at_us / last_decay_at_us`，与旧表一一对应。
- 衰减内置三档（默认 tier0=3.0、tier1=10.0、周期 3 天、useful_score+2.5、strength+1），与本项目 `MemoryDecayConfig` 同构，可用配置覆盖。
- 检索：全文 BM25 + 向量 + 重排；`filter` 维度为 namespace / scopes / tags / note_ids；**没有 memory_type 维度**，类型筛选放后处理。
- 笔记：`set_root`（每 namespace 一个根，路径必须在其下）、`upsert_file`（库内切片）、`get / get_many / chunks / get_chunk`、`search_preset("notes")` 返回 titles / contents / paths 三块、`search` 支持 `note_ids` 限定单篇。
- 提供商：`register_space` + `register_embedder`（同步回调）、`register_reranker`、`register_event_sink`；未注册时降级纯 BM25。向量按空间分开存，一个数据目录可容纳多提供商。
- 重排：书名块（titles）与路径块（paths）是纯全文探针，**不参与重排**；内容块与记忆检索可开重排。
- 图谱：`resolve / ego / path / apply_batch` 可用，本期不接入。
- 部署形态：p-memory 是 pip 依赖（容器内已装 0.3.4），源码仓库只作 API 参考，不参与运行时、不需要挂载进容器。

## 四、关键决策

| # | 决策 | 理由 | 替代方案（未采纳） |
|---|---|---|---|
| D1 | 单一数据目录 `plugin_data/astrbot_plugin_angel_memory/pmemory` | 库自带按空间存向量，切模型只新增 space，旧数据原地保留；分目录会让同一批记忆分裂 | 保留 `memory_{provider}` 多目录 |
| D2 | 记忆 namespace 固定 `angel/memory`；`scope` 直接写 `resolve_memory_scope` 的结果；读过滤 `scopes=[scope, "public"]`（去重） | scope 本就是动态字符串，语义为「公共 / 私有 / 群组范围」，与现有 memory_scope 完全同构；人格优先的解析逻辑一个字不改 | 把 memory_scope 映射成 namespace（多一层无意义转换） |
| D3 | 知识 namespace `angel/knowledge/{domain}`，域为 `gi / hsr / zzz / personal / angel`；群与域通过配置 `group_domain_map` 显式绑定 | 1305/1315 篇是特定游戏百科，无差别注入会串味；story 同样按域检索 | 全库召回（现状）、绑定只作加成 |
| D4 | 直接使用 p-memory 整数 id，不保留短 ID 与映射层 | 笔记全量重建后旧 short_id 必然失效；库内 id 唯一稳定 | 只给记忆保留短 ID（两套语义并存） |
| D5 | 笔记检索完全按 story 算法：三块检索 + 命中折叠 + 单篇 `note_ids` + 名字列定位 | 用户明确要求；库已完成折叠、计数、片段窗口 | 自研切片搜索与聚合 |
| D6 | 记忆效果保留在后处理：三档衰减配置、LLM 退休裁决、固定保留、灵魂共鸣、画像注入 | 用户要求保留短期记忆效果；p-memory 只产出候选，裁决权在我们 | 全交库默认策略 |
| D7 | 提供商同步桥（独立事件循环 + `EmbedCallbackError` 分类） | 库在调用线程持 GIL 同步调用回调，直接 await 会死锁 | 回调里 `asyncio.run` |
| D8 | 不留回退开关，验收后删除旧实现（Vector/Simple/Cognitive/Chroma/FAISS/Tantivy 切片/向量同步服务） | 双存储会让真相源含糊；旧代码无保留价值 | 保留旧模块与配置开关 |
| D9 | 工作树建在项目内 `.pai/.worktree/pmemory/`，测试直接在容器里跑 | 该路径在容器挂载范围内，无需同步；`.pai` 被 git 忽略，不会干扰主工作区；与 pr82 工作树同一惯例 | 仓库外另建工作树（容器看不到，需同步） |

## 五、口径与命名

- **namespace**：知识领域。记忆固定 `angel/memory`；知识 `angel/knowledge/{domain}`（domain 为空时为根）。
- **scope**：可见范围，取 `resolve_memory_scope` 的结果（人格键优先、会话 ID 次之、默认 public）。读过滤传 `[scope, "public"]`；scope 为 public 时只传 `["public"]`。
- **space**：嵌入空间，`angel-{model-slug}-{dimension}`；切提供商新增 space，旧 space 不删。
- **域映射**：`原神→gi`、`崩坏星穹铁道→hsr`、`绝区零→zzz`、`海豹的个人信息→personal`、`.angel/note→angel`。
- **绑定**：`group_domain_map: {群号: domain}`；未绑定群与私聊均不自动召回知识，只能工具主动搜索。`personal` 同样不默认召回。
- **向量化**：记忆域开；笔记域全部关闭（`set_vectorization(ns, "notes", False)`）。
- **重排**：记忆检索与笔记内容块都开；书名块/路径块按库语义不重排；未注册重排回调时自动降级。
- **ID**：工具展示整数 id；旧 UUID 写入 `metadata.legacy_id`。
- **记忆类型**：继续存中文枚举字符串，检索后按类型在后处理过滤/分组。

## 七、数据迁移

### 7.1 记忆（迁移）
- 源：`memory_center/index/simple_memory.db` 的 `memory_records`（475 条），标签从 `memory_tag_rel + global_tags` 还原。
- 映射：

| 旧字段 | p-memory |
|---|---|
| judgment / reasoning / memory_type | 同名 |
| tags | `tags` |
| memory_scope | `scope`（namespace 固定 `angel/memory`） |
| strength | `state.strength` |
| is_active | `state.pinned` |
| useful_count / useful_score / last_recalled_at / last_decay_at | `state.*_us`（秒→微秒） |
| created_at / updated_at / id | `metadata.legacy_id / created_at / updated_at` |

- 幂等：按 `metadata.legacy_id` 判重，重跑只更新不新增。
- 流程：dry-run 报告（条数、空 judgment、异常时间戳、类型与 scope 分布）→ 停插件 → `--apply` → 校验（条数、抽样 20 条逐字段比对）。

### 7.2 笔记（重建）
- 逐域 `set_root` → 遍历 Markdown → `upsert_file` → `update_index()`。
- 首次全量 1315 篇在后台任务执行，按域输出进度日志；导入完成前全文检索已可用。
- 增量：启动时按 mtime 扫描差异；`angel_note_create` 写文件后立即 `upsert_file`；文件删除时按路径定位 note id 后 `delete`。
- 向量：笔记域关闭向量化，不调 `sync`。

### 7.3 账本（不迁）
`user_ledger` / `group_ledger` 保留在 `simple_memory.db` 侧表，只读访问。

### 7.4 旧数据清理
- 迁移前做一次全量快照（插件数据目录，含 raw/ 与三个 provider 目录），只作灾备。
- 验收通过后删除旧 provider 目录、旧切片库与 FAISS/Chroma 数据，仓库内不保留旧实现代码；快照在确认稳定后手动删除。

## 八、分阶段实施

### P0 准备
- 删除旧工作树 `E:/github/pai-angel-memory`（`git worktree remove --force`，其未提交内容按计划弃用）；在 `.pai/.worktree/pmemory/astrbot_plugin_angel_memory` 新建工作树，分支沿用 `feature/p-memory-migration`；计划文件随之迁入工作树的 `plan/`。
- `requirements.txt` 固定 `p-memory==0.3.4`。
- 全量数据快照；迁移脚本完成 dry-run。

### P1 封装层
- `config.py` 命名与域映射；`kb.py` 懒打开单例、事件日志、启动自检（数据目录、space、counts）。
- `providers.py` 同步桥：超时、`EmbedCallbackError` 分类、维度探针、space 注册、重排注册。
- 单测：命名映射、state 秒↔微秒、无回调降级。

### P2 记忆替换
- `PMemoryMemoryRuntime` 实现协议全部方法：
  - `chained_recall` 不再复刻实体优先，直接把查询（含实体提示）交给 `kb.search`，结果后处理。
  - `feedback`：`memories.feedback` 处理有用/召回；`memory_actions` 的 update/merge 走 `upsert` / `delete`。
  - 退休：`memories.decay(policy=我们的配置)` 拿候选 → LLM 裁决 → `delete` / `upsert(pinned=True)`。
- `ComponentFactory` 只创建 p-memory runtime；工具、DeepMind、画像、注入切过去；移除短 ID 调用。

### P3 笔记替换
- `notes.py` 对齐 story：`search_blocks`、`search_docs`、`search_doc_chunks`、`resolve_note_id`。
- `angel_note_read`：note id → `notes.get` 取 source path → 按 offset/limit 读原文件。
- `angel_note_create`：写文件 → `upsert_file` → `update_index`。
- DeepMind 按绑定域检索，内容块开重排；删除 Tantivy 切片链路。

### P4 Web 与运维
- `memory_api`：概览、浏览、删除改读 p-memory；向量区改为 space 列表 + 各域就绪状态 + 计数。
- `notes_api`：搜索走三块检索，读取走 note id。
- `debug_api`：保留提供商探针，去掉旧索引组件依赖。
- 启动日志与健康信息：`[PMEMORY]` 初始化行、counts、space、各域 vector_ready。

### P5 验收与清理
- 容器内 pytest 全绿；执行迁移；跑验收清单。
- 删除旧实现与旧依赖；更新 AGENTS.md、README、CHANGELOG，`metadata.yaml` 递增版本。
- 计划归档按项目流程等生产验证通过后再做。

## 九、保留的记忆效果（后处理清单）

| 风险 | 影响 | 应对 |
|---|---|---|
| 工作树嵌在插件目录内 | 担心被 AstrBot 当插件扫描 | `.pai/` 不在 `data/plugins/` 顶层，扫描只看顶层目录；已有 pr82 工作树作先例 |

## 十四、已确认决策备忘

1. 迁移范围：记忆迁移、笔记重建、账本留侧表。
