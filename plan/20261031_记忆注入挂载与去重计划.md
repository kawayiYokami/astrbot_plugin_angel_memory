# 记忆注入挂载与去重计划

## 目标

1. 注入块的位置从「请求末尾的一条独立 user 消息」改为「紧跟在当前用户消息之后」。
2. 去重粒度是记忆条目，不是注入块：同一次处理里，同一条记忆只出现一次。
3. 判空粒度是部件，不是块：灵魂仪表盘、用户画像、记忆、笔记任一有内容才挂块，全空不挂。
4. 天使之心在场与不在场两种运行模式都要成立，账本是增强不是依赖。

## 现状

- 注入块通过 `request.contexts.append({"role": "user", "_no_save": True})` 追加，位置在历史之后，不是当前消息之后。
- 记忆检索没有跨消息去重，两条消息各召回各的，同一条记忆会出现两次。
- `<instruction>` 无条件拼进块，块永远非空。

## 差异举例

### 例一：两条消息召回同一条记忆

账本里有 M1、M2 两条待处理消息，记忆检索结果：

| 消息 | 召回记忆 |
|------|----------|
| M1 | 记忆A、记忆B |
| M2 | 记忆B、记忆C |

- 现状：M1 挂「A、B」，M2 挂「B、C」，记忆B 出现两次。
- 目标：M1 挂「A、B」，M2 只挂「C」。已注入集合 `{A, B}` 在两条消息间共享。

### 例二：后一条消息召回的记忆全被前一条挂过

账本里 M1 召回「A、B」，M2 召回「A」。

- 目标：M2 的记忆部件为空。
- 若 M2 此时没有灵魂仪表盘、画像、笔记，则 M2 不挂块；若灵魂仪表盘有读数，M2 仍挂一块，块里只有仪表盘，没有记忆段。

### 例三：没有任何部件有内容

记忆去重后为空、没有笔记、画像为空、灵魂系统关闭。

- 现状：仍会挂一块，里面只有 `<instruction>`。
- 目标：整块不挂。`<instruction>` 跟随块存在，自身不构成挂载理由。

### 例四：没有天使之心

请求里只有当前这一条消息，没有账本。

- 只给当前消息挂块，块的存在性靠反查请求里已有的块判断。
- 账本里可能存在的其他消息一概不管——它们本来就不在这次请求里。

### 例五：有账本，但账本里有消息在请求中已经丢失

账本记录 M1、M2、M3，请求的 `contexts` 里只找得到 M1、M2。

- 目标：只给 M1、M2 挂块，M3 丢弃，不凭账本回补。

## 为什么这么做

- **位置**：块挂在历史之后，模型看到的是一段与当前对话脱节的补充材料；挂在当前消息之后，它才是「针对这句话的背景」。这是注入语义的直接要求。
- **去重的收益是双向的**：省 token（一条记忆动辄几十上百字，重复出现按次计费）；也避免模型把同一事实当两条证据反复确认。
- **按部件判空**：块的每一部分都是可选增强，只有 `<instruction>` 是说明文字，不该在没有任何实质内容时独自撑起一个块。
- **依赖可选**：天使之心是可卸下的插件，账本只是它提供的便利。有账本时消息集合、ID、注入状态都有权威来源，跨请求去重才成立；没有时只能退到「当前消息 + 反查」，功能仍然完整，只是少了跨请求的那层记忆。

## 最终方案

已定为读法二：**每条消息各自召回、从前往后注入、注入期间记账**。

1. `deepmind._recall_per_message` 按 `chat_records` 里 user 消息的顺序逐条 `chained_recall`，当前消息补在末尾，保证最后一项一定是这条要回复的消息；没有账本时只剩它一条。
2. 共享一个 `seen` 集合，键是记忆 ID 的字符串。每条消息的记忆先过集合再组块，挂过后立刻记账，后面的消息不再重复带上同一条。
3. 挂载位置分两处，由消息是否在请求里决定：
   - 历史消息：在 `contexts` 中找到内容一致的那条用户消息（从尾部往前找，命中即停，不做全量扫描），把块作为一条 `_no_save` 的消息插在它之后；
   - 当前消息：走 `extra_user_content_parts`，位置由 `assemble_context` 拼在 `prompt` 之后。
   历史块只装记忆；`<instruction>`、灵魂仪表盘、用户画像、笔记只挂在当前消息那一条上，不随每条历史消息重复。
4. 判空按部件：记忆去重后为空且仪表盘、画像、笔记都为空，则整块不挂；`<instruction>` 跟随块存在，自身不构成挂载理由。
5. 账本里存在但 `contexts` 里找不到的消息直接丢弃，不猜位置、不回补。


## 边界

- 块必须标 `mark_as_temp()`，不落历史。
- `contexts` 里没有 `source_message_id`，定位只能按内容相等比对；图片占位符、被压缩改写的长消息会对不上，对不上时退回「最近一条 user」。
- 定位只在尾部做，命中即停，不做全量扫描或建索引。
- 判空的四个部件各自取「是否非空」，不引入新的配置项。

## 测试

- 两条消息召回同一条记忆：第二条块中该记忆不出现。
- 记忆全被去重掉、灵魂仪表盘有值：仍然挂块，块内只有仪表盘。
- 所有部件为空：不挂块，`extra_user_content_parts` 不增长。
- 无账本：只挂当前消息，重复调用不产生第二块。
- 有账本、账本消息多于请求消息：只挂请求里存在的那几条。
- 块不落历史：`model_dump_for_context()` 带 `_no_save`。
