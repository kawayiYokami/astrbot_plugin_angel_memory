# 群聊知识库可见性三态计划

## 用户原始指令

> 给所有群聊都增加一个知识库列表，列表带下拉，自动/手动/不可见。
> 自动=会自动 rag；手动=LLM 需要手动搜索；不可见=LLM 不知道有这个知识库也搜不到。

## 目标

1. 每个群聊对每个知识域（gi / hsr / zzz / personal / angel）各有一个三态开关。
2. WebUI 里能给每个群看到这份列表并逐项下拉修改，保存后即时生效。
3. 三态真正约束两条链路：DeepMind 自动注入、`angel_recall` 主动搜索。

## 数据模型

新增配置键 `group_knowledge_map`，与 `conversation_scope_map` 并列，JSON 文本：

```json
{
  "123456789": {"gi": "auto", "hsr": "manual", "zzz": "hidden"}
}
```

取值只有三个：`auto` / `manual` / `hidden`。

判定规则：

- 群未出现在表里，或该域未写 → `manual`。
- 写了非法值 → 回落 `manual` 并打一条告警日志。
- 旧配置 `group_domain_map` 继续读：命中的域视作 `auto`，其余域 `manual`。新表出现同名群时以新表为准。
- 私聊（拿不到群号）：全部域按 `manual` 处理——能搜、不自动注入。

## 语义

| 模式 | DeepMind 自动注入 | `angel_recall` 主动搜索 | LLM 是否知道该库存在 |
|---|---|---|---|
| auto | 是 | 是 | 是 |
| manual | 否 | 是 | 是 |
| hidden | 否 | 否 | 否 |

`hidden` 的域不出现在检索结果、不出现在返回文本、不出现在工具提示里。

## 改动点

后端：

- `_conf_schema.json`：新增 `group_knowledge_map`。
- `core/plugin_context.py`：解析校验三态表，提供 `get_group_knowledge_map()`、`resolve_knowledge_mode(group_id, domain)`、`list_knowledge_modes(group_id)`；配置更新时刷新。
- `core/services/retrieval_service.py`：自动召回判定从「绑定了某个域」改为「该域是 auto」。
- `core/services/note_index_service.py`：检索支持传入域白名单，未列入的域不查。
- `tools/angel_recall.py`：搜索域取「auto + manual」可见集合。
- `web_api/group_knowledge_api.py`：`GET` 返回群列表（群号、群名、五域模式），`POST` 保存三态表。

前端：

- `webui/src/views/GroupKnowledgeView.vue`：每个群一张卡片，五个下拉。
- 路由与侧边栏入口。

## 应该有的测试

1. 三态解析：缺省 `manual`、非法值回落、旧 `group_domain_map` 兼容为 `auto`。
2. 自动召回：只有 `auto` 域被注入；`manual` / `hidden` 都不注入；私聊不注入。
3. 主动搜索：`hidden` 域的结果被排除；`auto` 与 `manual` 都能搜到。
4. 群列表：来自群账本，配置里出现但账本没有的群也要列出。

## 边界与风险

- 群列表来源是群账本 `group_ledger`，从未产生过消息的群不会出现；需要群内有过对话或被登记。
- 只做运维侧开关，不提供群内指令，群成员无法自行改。
- 本次不改知识域的划分方式，仍是 raw/ 下五个目录。
- 保存走现有配置通道，不新增配置文件，可回滚。
- 前端页面构建产物需要重新构建才会生效；若本轮不构建，先交付 API 与后端语义，页面随后补。
