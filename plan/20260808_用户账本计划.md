# 用户账本（User Ledger）计划

日期：2026-08-08
关联：issue #73、PR #78（fix/user-id-tag-73）

## 背景与问题

画像记忆判定依赖 `is_user_id_tag` 用字符串形态猜测哪个 tag 是用户 ID，导致：

- `Test-Bot`、`weixin_oc_adapter`、`1998年10月19日`、`docker restart` 等描述性标签被误判为 ID
- tags 中出现两个"疑似 ID"时 `extract_user_id_from_tags` 返回空 → 画像静默消失
- 真实 ID（`10000` 5 位 QQ、`wxid_abcdef` 纯字母微信 ID、`alice` 纯字母 ID）被形态规则误杀

根因：系统没有沉淀权威用户 ID 的持久化载体。`sender_id` 只存在于会话级内存
（`_session_user_ids`）和一次性对话记录中，用完即弃，判定时被迫退化回形态猜测。

## 方案：持久化用户账本（仅作 ID 判定锚点）

### 用户账本表（memory_sql_manager 新增）

```
user_ledger(
  platform     TEXT NOT NULL,   -- 平台名（如 aiocqhttp/discord），不同平台同号是不同账本条目
  user_id      TEXT NOT NULL,   -- 权威 sender_id
  user_names   TEXT NOT NULL,   -- JSON 数组，同一用户在不同群/改名后的全部昵称，去重
  first_seen_at REAL NOT NULL,
  last_seen_at  REAL NOT NULL,
  PRIMARY KEY (platform, user_id)
)
```

### 群账本表（独立实体，仅记录不参与检索）

```
group_ledger(
  group_id     TEXT PRIMARY KEY,
  group_name   TEXT NOT NULL DEFAULT '',
  first_seen_at REAL NOT NULL,
  last_seen_at  REAL NOT NULL
)
```

群与人是完全不同的概念，不存在归属关系，不建关联。

接口：
- `upsert_user(platform, user_id, user_name)`：不存在则插入，存在则合并 user_names（去重）并刷新 last_seen_at
- `get_known_user_ids(platform="")`：全部已知 ID；带平台时返回该平台下 ID；不带平台时跨平台去重
- `get_user_names(platform, user_id)`：某平台下某用户全部昵称
- `upsert_group(group_id, group_name="")` / `get_known_group_ids()` / `get_group_name(group_id)`

### 登记点（deepmind.py）

事件处理链路拿到 `sender_id`/`sender_name` 后，先 upsert 进账本，再继续后续对话/反思流程。
真实用户消息（role=user 且非占位符）才登记；assistant 不登记。
同时登记群聊（`get_group_id()`），群名暂不异步获取。

### 判定改造（user_profile.py）

- `is_user_id_tag(tag, known_user_ids=None)`：
  - `known_user_ids` 非空且 `tag ∈ known_user_ids` → 直接判定为 ID（账本命中，不猜）
  - 否则回退现有形态猜兜底（冷启动、新用户、LLM 摘了账本外 ID）
- `extract_user_id_from_tags(tags, known_user_ids=None)`：优先返回 tags 中命中 known_user_ids 的 tag；
  兜底猜时保持「恰好一个疑似 ID」才返回
- `is_user_profile_tags(tags, known_user_ids=None)`：存在 ID（账本命中或猜中）+ 存在画像属性标签

### 检索链路：保持不变

- `recall_user_profiles` 不加 platform 参数，SQL 按 `sender_id` 精确匹配（现状行为）
- 画像判定锚点用 `账本全部 ID ∪ 当前会话真实 ID`
- 平台与群聊仅作为账本记录维度，不进入检索

### 调用点改造

| 位置 | 现状 | 改造 |
|---|---|---|
| `user_profile_service._is_valid_user_id` | 形态猜 sender_id | sender_id 权威，只过滤空/占位符（Unknown/assistant/user），不再猜 |
| `user_profile_service.format_session_profiles` | 猜 tags 里哪个是 ID | 传 `_session_user_ids[sid]` 作 known_user_ids |
| `memory_sql_manager._recall_user_profiles_sync` | `is_user_profile_tags(mem.tags)` 再猜一遍 | 传账本 ID 并集作 known_user_ids |
| `web_api/profile_api` 用户列表 | 全库扫描 + 猜 | 读账本展示平台/ID/昵称 + 群账本展示群聊 |

## 边界

- 冷启动：账本为空时 `is_user_id_tag` 走形态兜底，不阻断首批画像
- 同人多名：`user_names` 累积全部昵称，渲染时当前会话昵称优先
- 跨平台同号：`(platform, user_id)` 复合主键，不同平台不同账本条目，互不混同
- 群聊：仅记录群实体，与人无归属关系，不参与记忆检索
- `is_user_id_tag` 保留兜底语义：账本未命中 ≠ 不是 ID，只是回到猜

## 测试

- 账本 upsert：新增、同平台同 ID 合并昵称、去重、占位符忽略、跨平台同号独立
- 群账本：upsert、群名更新、忽略空/占位符
- `is_user_id_tag`：账本命中即 ID；未命中回退猜（保留 issue #73 全部用例）
- `extract_user_id_from_tags`：传 known_user_ids 时 `["Test-Bot", "1023456789", "事实属性"]` 正确返回 `1023456789`
- `is_user_profile_tags`：传 known_user_ids 时多 tag 不再误杀
- 回归：`tests/test_user_profile_service.py` 全部通过
