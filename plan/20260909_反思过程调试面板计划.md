# 反思过程调试面板计划（最近 10 次 RAG 整理记录）

日期：2026-09-09

## 用户原始指令

> 我觉得需要在内存中记录最近10次 rag整理的提示词和返回结果。在webui上可以查看，如果有问题的时候就可以反馈。

## 背景

Issue #80 暴露核心问题：反思归纳生成的记忆，tags 由 LLM 自由发挥，经常漏写用户 ID 与画像属性标签，导致画像判定静默失败——记忆落库但永不进画像，无任何报错，排查极难。

根治方案（模型层增加"主体用户 ID"字段）工程量大、需要迁移存储。本计划采用可观测性方案：让反思归纳的输入（提示词）与输出（LLM 返回）可见、可复现，问题从"静默"变"可反馈"。

## 目标

- 内存中保留最近 10 次反思归纳的提示词与 LLM 返回结果
- WebUI 查看，支持复制，便于用户出问题时反馈
- 失败的分析同样入档（失败更要看得见）

## 方案

### 后端（core/deepmind.py 附近）

1. 新建环形缓冲 `ReflectionTraceBuffer`（`deque(maxlen=10)` + 锁，线程安全）：
   - 每次反思分析记录：时间戳、会话 ID、模型名、构造的提示词全文、LLM 原始返回（memory_actions JSON）、分析是否成功（异常信息）
2. 记录点两处（deepmind.py）：
   - `_build_reflection_input` 拿到构造好的提示词后 → 入档（此时结果未知，标记 pending）
   - 分析完成/异常出口 → 回填结果或异常信息
3. 新增 API 端点：`GET` 返回最近 10 条记录（无鉴权，仅本机 WebUI 使用）

### 前端（webui）

4. 现有 DebugView.vue 扩展一个"反思记录"区块（或新增独立视图），卡片式展示：
   - 时间 / 会话 ID / 模型名 / 成功或失败徽标
   - 提示词与返回结果可折叠 JSON 展示
   - 每条一个"复制"按钮（复制完整 JSON 到剪贴板）

## 边界（不做的事）

- **不落盘**：纯内存，重启即清空；不做持久化查询
- **不记录检索注入环节**：只记反思归纳（`_trigger_reflection_if_needed` → 分析流程），不含 organize_and_inject_memories 的记忆注入
- **不主动外发**：记录只存在本机内存，复制靠用户手动
- **不改数据模型**：不动 BaseMemory / SQL / 向量 metadata
- **不解决画像归属**：本计划只做可见性，不做归属判定修复

## 风险与约束

- 提示词含用户对话内容明文：WebUI 本机展示可接受，页面标注"含隐私内容，仅本机调试用"
- 内存占用：10 条 × 单条提示词 + 返回，量级 KB~数十 KB，无压力；不设截断（截断会破坏反馈可用性）
- WebUI 无鉴权的前提是插件本就只服务本机 AstrBot，与既有页面一致

## 统一口径

- "RAG 整理" = 反思归纳（reflection）：对话 → LLM 分析 → 记忆三元组（judgment/reasoning/tags）的生成过程
- "反馈" = 用户在 WebUI 复制记录，贴给维护者排查

## 测试

- 缓冲满 10 条后滚动丢弃最旧
- 成功与失败分析均入档，失败带异常信息
- 并发写入（asyncio 多任务）不丢记录、不抛异常
- API 端点返回结构与字段完整

## 最终呈现（验收样例）

WebUI 调试页出现"反思记录"区块，展示最近 10 次分析：提示词与返回结果可展开、可复制；重启插件后清空。
