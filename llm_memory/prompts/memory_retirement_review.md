# 淘汰记忆终审裁决

你的任务是审核一批因长期沉寂而面临清理的记忆，裁决其保留（`keep`）或删除（`delete`）。
只输出符合格式的 JSON，不输出任何解释或代码块标记。

---

## 输入格式说明

输入清单每条占两行：
```
- id:编号 日期 - 结论
  理由：依据（若无则此行省略）
```

---

## 裁决准则

### 1. 判 `keep`（长期有效，不可再生）
命中以下任意一项，立即判定 `keep`：
- **用户画像**：群友本人的固定特征（身份、圈子、长期偏好、擅长技能、真实经历）。
- **自身设定**：助手自身的固定认知与设定（外貌、性格、身份、能力边界、与人的稳定关系）。
- **约定与承诺**：与群友说定、未来需要兑现的事项。
- **长期推进中**：持续跟进的项目、任务、研究方向。
- **稳定偏好与长期要求**：群友提出的长期遵守规则、禁忌或交互偏好。
- **拿不准/信息模糊**：难以判断价值的条目，一律判 `keep`。

### 2. 判 `delete`（一次性或无复用价值）
仅当内容完全属于以下情况时，才判定 `delete`：
- **一次性操作与过程流水账**：仅记录“帮某人查了天气/改了文件/点了按钮”，不含可复用结论。
- **临时状态**：单次的情绪发泄、已过期的临时安排或待办。
- **低价值噪音**：寒暄、表情、发图发文件等过程记录。
- **过时冲突**：已被后续更完整、更准确的记忆完全取代。

---

## 输出规范

整段响应仅输出一次合法 JSON：

```json
{
  "decisions": [
    { "id": "m0", "verdict": "keep", "reason": "群友长期技术画像" },
    { "id": "m1", "verdict": "delete", "reason": "一次性操作流水账，无复用价值" }
  ]
}
```

- `id`：必须与清单中的编号完全一致。
- `verdict`：仅限 `"keep"` 或 `"delete"`。
- `reason`：30 字以内简明中文理由。
- **拿不准的不必写入 `decisions`**（未出现的条目系统默认保持原样）。严禁编造不存在的编号。
