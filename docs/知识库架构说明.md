# 知识库架构说明

从「整篇文档塞进上下文」升级到「按域分库 + 切片检索 + 主动查阅」的对比说明。

---

## 一、检索成本的来源

### 传统方案：整篇塞入

```
文档 → 整篇拼进提示词 → 主模型自己找
```

**问题**：
- 一篇长文里 90% 与当前问题无关
- 上下文被占满，真正的对话被挤掉
- 文档一多就无法放进同一轮

### Angel Memory：先定位，再按需读

```
文件 → 切片入库 → 命中片段 → 需要时读原文
```

**优势**：
- 只带命中位置，不带整篇
- 定位与阅读分开：先给线索，再决定要不要展开
- 上下文留给对话本身

---

## 二、文件分类对检索的影响

### 传统方案：扁平存储

```
- doc_001: "胡桃的装扮..."（无分类信息）
- doc_002: "武器故事..."（无分类信息）
```

**问题**：
- 无法利用目录语义
- 「苹果」分不清水果、公司还是手机
- 同名概念相互干扰

### Angel Memory：目录即知识域

```
raw/
├── 原神/
├── 崩坏星穹铁道/
├── 绝区零/
├── 海豹的个人信息/
└── .angel/note/
```

**优势**：

**域内检索**：
- 每个群对每个域单独设定可见性
- 检索只在允许的域里进行
- 同名概念被域隔开

**可见性可控**：
| 用法 | 自动带进对话 | 主动搜索 | AI 是否知道存在 |
|------|--------------|----------|------------------|
| 自动 | 会 | 能 | 知道 |
| 手动 | 不会 | 能 | 知道 |
| 不可见 | 不会 | 不能 | 不知道 |

没配过的群与私聊默认全部「手动」。

## 三、切分与返回策略

### 传统方案：固定长度切分 + 返回正文

```
文档 → 按固定字数切分 → 检索返回大段正文
```

**问题一：切分困境**
- 太大：检索不精确
- 太小：上下文丢失
- 重叠切分：存储翻倍

**问题二：正文污染思考**
- 大段原文直接注入会「暗示」答案
- 无关细节占据上下文

### Angel Memory：按段落切片 + 三块返回

**切分策略**

- 由统一记忆库按文件结构切片，保留代码块与表格完整
- 每片记录行号，便于回到原文定位
- 文件改动后重新切片，旧片自动失效

**返回策略：标题 / 内容 / 路径三块**

| 块 | 用途 |
|----|------|
| 标题 | 命中标题，说明这篇讲什么 |
| 内容 | 命中片段，带摘要 |
| 路径 | 命中目录或文件名 |

**为什么分三块更好**

1. **减少上下文污染**：标题和路径只给线索，不塞正文
2. **保留思考独立**：主模型自己判断相关性
3. **按需深入**：需要细节时用笔记 ID 分页读原文

**按需深入机制**：
- 第一轮：给标题、片段摘要、路径
- 模型判断哪些相关
- 第二轮：按笔记 ID 读取正文（默认单次上限 3 万字符，返回是否还有更多）

## 四、记忆系统

### 传统知识库：无记忆能力

```
传统知识库 = 静态文档存储
```

**缺失**：
- 记不住用户说过的话
- 学不到偏好
- 每次都是「第一次见面」

### Angel Memory：记忆 + 知识库

| 能力 | 说明 |
|------|------|
| 记住对话 | 用户说过的关键信息 |
| 学习偏好 | 喜欢什么、介意什么 |
| 理解关系 | 与谁亲近、属于哪个圈子 |
| 积累经验 | 从相处里提炼认知 |

**记忆元结构**：
```
论断：用户喜欢吃苹果
理由：多次提到，并明确说过喜欢口感
标签：[偏好, 食物, 水果]
状态快照：写下这条时的灵魂状态
```

**变淡与留下**：

| 档位 | 条件 | 策略 |
|------|------|------|
| T0 易逝 | useful_score < 3 | 时间驱动变淡 |
| T1 待证 | 3 ≤ score < 10 | 召回后无用时变淡 |
| T2 核心 | score ≥ 10 | 不再变淡 |

淡到尽头的交给模型审查：判留升为永久记忆，判删才删除。审查失败整批不动。

**记忆 vs 笔记**：

| 维度 | 记忆 | 笔记 |
|------|------|------|
| 来源 | 对话中积累 | 用户投喂或 AI 自己写 |
| 内容 | 人、事、关系、经验 | 资料、攻略、设定 |
| 更新 | 自动 | 改文件即可 |
| 遗忘 | 三档变淡 + 审查 | 永久，除非删文件 |

## 五、灵魂系统（记忆的附件）

### 传统知识库：静态配置

```
temperature: 0.7
max_tokens: 2000
top_k: 10
```

**问题**：参数固定，无论什么情境都一样。

### Angel Memory：四对情绪轴

| 轴 | 0.0 这一端 | 1.0 这一端 |
|------|-----------|-----------|
| joy | 哀伤 | 喜欢 |
| anger | 害怕 | 生气 |
| surprise | 意料之中 | 出乎意料 |
| disgust | 认可 | 厌恶 |

每轴取值 0.0 ~ 1.0，0.5 为中性，四轴独立打分。

**情绪对应**：喜则外向、悲则内向；意料之中则好奇、出乎意料则观望；怒则详尽、恐则简洁；认可则活泼、厌恶则严肃。

检索条数与记忆生成条数属工程参数，走固定配置，不随情绪波动。

**橡皮筋算法**：情绪倾向回归中线，离中线越远越难继续偏离。

**双轨调整**：
- 灵魂共鸣（被动）：检索到的记忆带着当时情绪读数，按记忆强度加权牵引当前状态
- 灵魂反思（主动）：对话后小模型给四项情绪打分，力度更大

**实际效果**：
```
用户聊起开心的事
→ 共鸣让状态偏积极
→ 回忆深度上升：多想起几条
→ 表达欲望上升：回复更详尽
→ 创造力上升：表达更活泼
```

**注入形状**：
```

• 认知倾向: 指导 ████       好奇 [0.42]

• 情绪倾向: 严肃 ███████    活泼 [0.85]
</soul_state>
```

## 总结对比

| 维度 | 简单向量库 | Angel Memory |
|------|-----------|--------------|
| **检索方式** | 整篇向量化，逐条调用 | 切片入库，按需读原文 |
| **分类能力** | 扁平存储 | 目录即知识域，域内检索 |
| **可见性** | 全域可见 | 每群每库三态 |
| **返回策略** | 返回大段正文 | 标题 / 片段 / 路径三块 |
| **记忆能力** | 无 | 三档变淡 + 退休审查 |
| **状态系统** | 静态配置 | 四维状态 + 共鸣 |

**升级价值**：
- 上下文更干净：只带线索，正文按需读
- 命中更准：域隔离 + 重排
- 记忆更耐久：重要内容升为永久
- 认知更完整：记忆 + 知识 + 状态三位一体
