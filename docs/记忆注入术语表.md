# 记忆注入术语表

每个概念只有一个正式名。对话、代码注释、日志、文档都用这一个名字，旧叫法一律不再使用。

## 速查

| 概念 | 一句话 |
|---|---|
| 快照 | 天使之心交过来的这一轮对话记录 |
| 上下文 | 本次请求真正发给模型的那段历史消息 |
| 长期库 | 全部记忆的存放处 |
| 检索 | 拿一句话去长期库找相关记忆 |
| 短期记忆 | 本次会话记住了哪些记忆，每条各自跟着最后召回它的那条消息 |
| 记忆条目 | 短期记忆里的一条记录，记忆本体加召回来源 |
| 召回来源 | 最后一次把这条记忆带进来的那条用户消息 |
| 召回 | 记忆被检索到并写进短期记忆，每次都刷新召回来源 |
| 在场消息 | 本次请求里还存在的用户消息 |
| 离场 | 召回来源已不在上下文，记忆随之离开 |
| 离场反思 | 记忆离开时连同那条消息一起交给小模型复盘 |
| 轮次反思 | 每轮对话结束后照常跑的那次复盘 |
| 注入 | 把记忆写成文字塞进这次请求 |
| 注入块 | 被 `<system_reminder>` 包起来的那段内容 |
| 挂回历史 | 备用注入路径，把记忆挂回各条历史消息后面 |

## 一、数据来源

### 快照

天使之心交过来的这一轮对话记录，本进程只读不改。原生模式下没有这份东西。

落点：`chat_records`
旧叫法（不再使用）：账本、天使之心账本、整份记录

### 上下文

本次请求真正发给模型的那段历史消息，每条只有 `role` 和 `content`，没有消息 ID。

落点：`request.contexts`
旧叫法（不再使用）：对话历史、请求上下文

### 长期库

全部记忆的存放处，由 p-memory 承载。短期记忆里的内容来自这里，但进入之后不再回查。

落点：`pmemory/` 封装层
旧叫法（不再使用）：库、数据库

### 检索

拿一句话去长期库找相关记忆。一次请求只在记忆写进短期记忆之前做一次，注入时不再检索。

落点：`DeepMindRetrievalService`
旧叫法（不再使用）：召回

## 二、短期记忆

### 短期记忆

本次会话记住了哪些记忆，每条各自跟着最后召回它的那条消息。每种记忆类型有各自的槽位数，满了按最久没被召回的先后淘汰。

落点：`SessionMemory` / `SessionMemoryManager`
旧叫法（不再使用）：短期仓、会话工作记忆缓存、工作记忆缓存

### 记忆条目

短期记忆里的一条记录，一行同时装着记忆本体和它的召回来源：`added_at`（首次写进来的时间）、`recalled_at`（最后一次被召回的时间）、`bound_message_id`、`bound_message_text`、`memory`。

落点：`MemoryItem`
旧叫法（不再使用）：引用、失效引用、记忆项

### 召回来源

最后一次把这条记忆带进短期记忆的那条用户消息，记消息 ID 与正文。正文存下来是为了跟上下文比对，判断这条消息还在不在。

落点：`bound_message_id` / `bound_message_text`
旧叫法（不再使用）：绑定消息、带入这条记忆的消息、目标消息

### 召回

记忆被检索到并写进短期记忆。已经在表里的不会新建，只刷新 `recalled_at` 与召回来源，`added_at` 保持不变。

落点：`SessionMemory.add_memories` / `MemoryItem.recall_again`
旧叫法（不再使用）：进入、入场、入仓

### 槽位淘汰

某种记忆类型超过槽位数时，按 `(recalled_at, added_at)` 升序淘汰，最久没被召回的先走。只看类型内，跨类型不互相挤。

落点：`SessionMemory._cleanup_by_capacity`
旧叫法（不再使用）：容量上限、生命值、进入侧去重

### 在场消息

本次请求里还存在的用户消息正文。取 `request.contexts` 里 `role == "user"` 的纯文本，再加上本轮当前这条发言。

落点：`DeepMind._context_user_texts`
旧叫法（不再使用）：存活消息、真实存在的消息、未丢失的消息

### 离场

召回来源已不在上下文，记忆随之离开短期记忆。说的是消息不在了，不是时间到了。判定按正文包含：条目存的是纯正文，上下文里那条可能还带发言人前缀与时间标签，正文出现在某条在场消息里就算还在。短句重复只会多留一条，不会误杀。

落点：`SessionMemory.prune_departed` / `SessionMemoryManager.prune_departed_from_session`
旧叫法（不再使用）：过期、失效、消息走了、`prune_absent_messages`

## 三、反思

### 离场反思

记忆离场时，把它的正文和召回来源一起交给小模型复盘。这时没有对应回答，回答一栏留空。

落点：`DeepMind._reflect_departed_memories`
旧叫法（不再使用）：离场送审、反思过期记忆、送去反思

### 轮次反思

每轮对话结束后照常跑的那次复盘，账目按实际挂进请求的那批记忆写。

落点：`after_message_sent` → `memory_runtime.feedback`
旧叫法（不再使用）：常规反思、每轮反思、反馈

## 四、注入

### 注入

把记忆写成文字塞进这次请求。注入不检索，直接取短期记忆里的全部条目。

落点：`DeepMindInjectionService`
旧叫法（不再使用）：挂载、喂给主意识

### 注入块

被 `<system_reminder>` 包起来的那段内容，默认只有末尾这一块，装仪表盘、画像、笔记与记忆。行为守则走系统提示词，不进注入块。

落点：`_render_block` / `_attach_current_block`
旧叫法（不再使用）：上下文块、系统上下文块、块

### 注入位置

默认只在上下文末尾追加一条 `_no_save` 用户消息，位置在本轮发言之前，历史消息一行不碰。

落点：`_attach_current_block`
旧叫法（不再使用）：挂载点、附加内容、extra_user_content_parts

### 挂回历史

备用注入路径，默认关闭（`INJECT_HISTORY_BLOCKS`）。打开后把记忆挂回各自召回的某条历史消息后面，靠快照与上下文从尾部一对一配对定位。群聊里重复短句多时容易配错位置，所以不默认启用。

落点：`attach_history_blocks` / `_message_order`
旧叫法（不再使用）：尾部对齐配对、历史块、尾部比对

## 有待处理的命名

`chained_recall` 这个名字指的是四步串联的检索机制，那套机制在 p-memory 接管检索时已经不存在了。现在它只是一次普通检索，参数 `per_type_limit` 也随之失去作用。名字暂时保留，处理方式待定。

## 使用约定

- 说「短期记忆」不说「短期仓」；说「离场」不说「过期」。
- 说「召回来源」不说「绑定消息」。
- 两套反思必须叫全名，不简称「反思」。
- 遇到没收录的词，先确认它是不是已经在别处有了正式名，再决定要不要新增。
