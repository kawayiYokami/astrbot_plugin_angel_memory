# 记忆库架构与迁移说明

## 1. 文档目的
- 说明本项目当前的「数据落点 + 检索链路」架构。
- 给跨端（服务端 / 桌面端）迁移提供统一认知。
- 本文聚焦架构与数据流，不讨论具体代码细节。

## 2. 核心结论（一句话）
- **记忆与笔记都由统一记忆库承载**；插件侧只做提供商回调与后处理，不再维护第二套存储。

## 3. 术语与分层

### 3.1 承载层
- 统一记忆库（`p-memory`，Rust 扩展，pip 依赖）保存记忆本体、笔记切片与全文/向量索引。
- 职责：持久化、检索、排序、衰减、备份快照。
- 要求：任何记忆或笔记写入都经它落盘。

### 3.2 回调层
- 嵌入回调：把文本转向量，按提供商与维度注册成独立空间。
- 重排回调：对候选重新排序。
- 特点：未注册时库自动降级为纯全文，检索仍然可用。

### 3.3 后处理层
- 结果转换、类型分组、灵魂共鸣、画像识别、注入拼装、退休裁决、Web 展示。
- 特点：只读库产出的候选，不承担存储真相。

## 4. 记忆方案（Memory Store Strategy）

### 4.1 数据主线
1. 写入：主流程经 `MemoryRuntime` 写入记忆库，scope 由会话解析结果决定。
2. 检索：全文召回为主，向量可用时融合，重排可用时二次排序。
3. 维护：每天凌晨 4 点执行一次衰减与退休审查。
4. 备份：每日 JSON 快照，最多保留 3 份。

### 4.2 为什么这样设计
- 不把插件当数据库，迁移与重建成本都在库内。
- 无嵌入模型环境下仍然可用，向量只是增强。
- 跨端只需对齐库的数据目录语义，不必对齐两套索引。

## 5. 笔记与知识库方案

### 5.1 文件是真相
- `raw/` 下的 Markdown / TXT 是唯一真相源。
- 库只保存切片与索引，可随时按文件重建。
- 目录即知识域：`原神` / `崩坏星穹铁道` / `绝区零` / `海豹的个人信息` / `.angel/note`。

### 5.2 检索形状
- 三块检索：书名（标题命中）、内容（正文片段）、路径（目录与文件名命中）。
- 单篇限定：按笔记 ID 收窄到一篇。
- 路径定位：先搜名字列，再逐条校验路径，避免同名误配。

### 5.3 一致性保障
- 启动：全量扫描各域目录，按修改时间增量同步。
- 运行：文件变化后一分钟内自动纳入。
- 异常：库报错时该次检索返回空并记录异常，不污染已有索引。

## 6. 两种部署模式

### 6.1 仅全文（最小配置）
- 组成：统一记忆库 + 全文检索。
- 不启用：嵌入、重排。
- 适用：只想先把记忆与知识库跑起来。
- 检索行为：全文召回直出，结果可解释。

### 6.2 全文 + 重排 + 向量（推荐）
- 组成：统一记忆库 + 重排回调 + 嵌入回调。
- 适用：追求命中率与语义泛化。
- 检索行为：向量与全文融合，候选再过重排。

**推荐优先级**：只配 `provider_id` 即可用；加 `rerank_provider_id` 提升明显；嵌入可选。

## 7. 跨端迁移建议（按阶段）

### 阶段 1：对齐承载层
- 迁移数据目录，确认记忆与笔记都能读出来。
- 建立备份与恢复流程（每日 JSON 快照）。

### 阶段 2：对齐回调层
- 先不配嵌入，确认纯全文检索质量与延迟。
- 再接入重排，观察候选排序变化。

### 阶段 3：可选接入向量
- 嵌入空间按「提供商 + 维度」独立存放，切换模型只新增空间。
- 旧空间不删除，随时可回退。

## 8. 迁移时必须坚持的边界
- 不允许插件侧再维护一套记忆存储。
- 不允许把知识库正文全量灌进对话上下文。
- 不允许检索策略与可观测性脱节：降级必须有原因日志。

## 9. 可观测与验收

### 9.1 必备指标
- 记忆总数、笔记数、标签数（管理面板总览）。
- 检索延迟与是否发生降级。
- 每日备份是否成功、当前保留份数。

### 9.2 无向量验收标准
- 关闭嵌入后记忆与笔记仍可稳定检索。
- 全文结果可解释、可复现。
- 数据恢复仅依赖库目录与 JSON 快照即可完成。

## 10. 迁移提示
- 切换到桌面端目录后，优先确认三件事：
1. 记忆库数据目录是否随插件数据一起迁移。
2. `raw/` 下的五个知识域目录是否完整。
3. 是否把嵌入与重排定义为「可选增强」而非必需依赖。

## 11. 关键数据模型（对齐基线）

### 11.1 记忆记录
- `id`：库内整数主键。
- `memory_type`：中文枚举（知识 / 事件 / 技能 / 任务 / 情感）。
- `judgment`：可检索核心论断。
- `reasoning`：背景解释。
- `tags`：直接挂在记录上，不走关系表。
- `scope`：可见范围，人格键优先、会话 ID 次之、默认 `public`。
- `state`：`strength` / `pinned` / `useful_count` / `useful_score` / `last_recalled_at_us` / `last_decay_at_us`。
- `metadata`：`legacy_id`、`soul_state`、`source_ids` 等附属信息。

### 11.2 笔记记录
- `id`：库内整数 ID（工具与面板都用它）。
- `source`：文件绝对路径。
- `title`：首个标题行。
- `chunk`：段落切片，带 `offset` 行号。

### 11.3 导出快照
- 顶层包含 `records`、`global_tags`、`memory_tag_rel`。
- 标签内嵌在每条记录里，回灌时优先读该字段。
- 已存在的记录按 `id` 跳过，不覆盖。

## 12. 遗忘算法（实现机制与关键参数）

### 12.1 算法目标
- 让记忆「可成长也可遗忘」，避免无限膨胀。
- 平衡三件事：新记忆淘汰速度、有效记忆保留能力、核心记忆稳定性。

### 12.2 三档分层规则（按 `useful_score`）
- **T0（易逝档）**：`useful_score < tier0_threshold`
- **T1（待证档）**：`tier0_threshold <= useful_score < tier1_threshold`
- **T2（核心档）**：`useful_score >= tier1_threshold`

### 12.3 行为机制（当前实现）
- 记忆被判定「有用」时：
1. `useful_count += 1`
2. `useful_score += consolidate_speed`
3. 更新 `last_recalled_at`

- 记忆「被召回但无用」时：
1. 仅对 **T1** 执行衰减
2. `strength -= 1`（下限 0）

- 自然遗忘（时间驱动）：
1. 仅对 **T0** 执行
2. 按周期扣减 `strength`
3. 周期计算：`effective_cycle_days = round(cycle_tier0_days / (forget_speed * tier0_forget_speed))`，最小 1 天

- 核心记忆（T2）：不参与自然遗忘，也不因「召回无用」衰减。

- 固定保留（`pinned`）：主动铭记的记忆，不参与任何衰减。

### 12.4 删除不再自动发生
- 强度归零只代表「这段时间没被用上」，不等于没有价值。
- 归零记忆先进入退休审查：判 keep 的固定为永久记忆，判 delete 的才真正删除。
- 审查失败（模型没给结论或调用异常）时整批跳过，一条都不删。

### 12.5 默认参数（当前代码默认值）
- `tier0_threshold = 3.0`
- `tier1_threshold = 10.0`
- `consolidate_speed = 2.5`
- `cycle_tier0_days = 3`
- `forget_speed = 1.0`
- `tier0_forget_speed = 1.0`

### 12.6 参数覆盖入口（配置）
- 路径：`memory_behavior.decay_policy_override`
- 开关：`enabled=true` 时才启用自定义参数覆盖
- 保护规则：
1. `tier1_threshold < tier0_threshold` 时自动拉齐
2. 速度与周期参数均有最小保护值，避免 0 或负值

### 12.7 与跨端迁移的关系
- 衰减属于记忆业务语义，不随存储后端变化。
- 迁移时保留 `state` 里的衰减字段，避免迁移后记忆被一次性补衰。

---

本说明可作为跨端统一架构基线：
**先对齐承载层，再谈检索增强；先可用稳定，后语义提升。**
